# Домашнє завдання 10. Жадібні алгоритми та динамічне програмування

## Завдання 1. Порівняння ефективності видачі решти

Для монет `[50, 25, 10, 5, 2, 1]` реалізовано дві функції:
1. `find_coins_greedy` — жадібний алгоритм.
2. `find_min_coins` — динамічне програмування (таблиця заповнюється знизу вгору).

### Час виконання (на 1 виклик)

| Сума | Жадібний алгоритм | Динамічне програмування |
|-----:|------------------:|------------------------:|
| 113 | 0.00000036 с | 0.00003394 с |
| 1 000 | 0.00000016 с | 0.00032929 с |
| 10 000 | 0.00000013 с | 0.00333949 с |
| 50 000 | 0.00000015 с | 0.01887605 с |

### Складність (Big-O)

Тут $S$ — сума решти, $k$ — кількість номіналів (у нас $k = 6$).

| Алгоритм | Час | Пам'ять |
|----------|-----|---------|
| Жадібний | $O(k)$, фактично $O(1)$ — не залежить від $S$ | $O(k)$ |
| Динамічне програмування | $O(S \cdot k)$ — рахує оптимум для кожної суми від $1$ до $S$ | $O(S)$ — таблиці `min_coins` і `last_coin` |

### Висновки

1. **Швидкість:** жадібний алгоритм майже не залежить від суми, бо робить лише по одному діленню (`//`) і остачі (`%`) на кожен номінал. Динамічне програмування сповільнюється лінійно зі зростанням суми та потребує більше пам'яті.
2. **Коли що використовувати:**
   * Для **канонічних наборів монет** (як у завданні) жадібний алгоритм завжди дає оптимальний результат, тож він кращий: швидший і економніший.
   * **Динамічне програмування** потрібне для **неканонічних наборів**. Наприклад, для `[10, 6, 1]` і суми `12` жадібний алгоритм видасть `10 + 1 + 1` (3 монети), а оптимум — `6 + 6` (2 монети).
